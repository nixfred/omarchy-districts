Audit date: 2026-10-07. This is the canonical project requirement tracker, recovered from the original project notes and requirement conversations. Thirty deduplicated obligations are split into 43 acceptance and support checks. Exact color mapping, timing/bounds, privacy guards and the named Desk/surprise designs are implementation choices unless explicitly requested. Detailed conversation identifiers, machine receipts, backups and historical private branch provenance are retained in a separate local source ledger; they are not part of public source.

- **Open delivery:** exact published-commit CI, installed file parity, scoped plugin load and native acceptance remain separate gates. Source synchronization alone does not complete them.
- **2026-10-07 completion pass (3.0.0, 34 runtime files):** implemented D-02 persistent side pace dock, D-12 reported-state agent glow, D-15 real agent and district names, D-37 family collapse/expand. Fixed a live Claude inventory bug (interactive sessions report `status`, not `state`, so 12 of 13 live Claude sessions showed `unknown`), a 7px Inspector overflow at the 912×512 minimum, and a stale grouping test that clicked the pre-2067e5e heading position. Checks run this pass: 233 Python, 9 JavaScript suites, 2 timezone runs, 41 Qt cases across six suites, and native fixtures in an isolated Omarchy 4.0.2 Test Drive VM (integrated, interaction, pagination, grouping, application, activity, resolutions, skyline, Desk, pane, organize, native, live bridge, performance all PASS). `stress` times out on IPC close in the VM at 512 windows/512 workspaces/4K (one core pegged by software rendering; identical on the untouched c1924fb baseline). `activation_health` needs an installation receipt and runs after install.

**Status key:** **Running** means present in the installed 2.2.3 runtime, with the stated evidence limits. **Built/tested** means present in unpublished 3.0 with recorded source/fixture evidence. **Partial** means some semantics/providers or acceptance criteria remain unsupported. **Not implemented** means absent from the inspected release. **Blocked** means delivery cannot proceed. Every built/tested 3.0 row still needs exact published-commit CI, installation parity and scoped load verification before installed acceptance.
